# 🗂️ 데이터 스펙

게임 로직(고정)과 콘텐츠 데이터(가변)를 분리한 구조입니다. 모든 상태는 브라우저
`localStorage` 키 **`svt_lyrics_quiz_v1`** 에 저장됩니다.

---

## 1. 데이터 모델

```jsonc
{
  "songs": [                      // 곡 목록 (편집 가능)
    { "id": "s2", "name": "13월의 춤 (Lilili Yabbay)", "part": "브릿지 · 퍼포먼스팀", "diff": "상" }
    // ...
  ],
  "content": {                    // 곡 id별 콘텐츠 (편집 가능)
    "s2": { "lyrics": "…", "mv": "https://youtu.be/…", "time": "2:05" }
    // ...
  },
  "album": {                      // 곡 id별 힌트 메타(발매연도/앨범종류). 앱이 이 값을 우선 사용
    "s2": { "year": 2017, "type": "정규" }
    // type ∈ 정규 / 미니 / 싱글 / 디지털 싱글 / 스페셜 / 베스트
  },
  "config": {                     // 게임 방식 설정 (아래는 실제 기본값)
    "timerOn": true,
    "timerSec": 20,
    "teamMode": false,
    "teamNames": ["팀 1", "팀 2"],
    "mc": true,                   // 4지선다(객관식) 모드
    "teamBlind": true,            // 팀 선택 가리기(모든 팀 제출 전 비공개)
    "autoHost": false,            // 자동 진행(오토 호스트)
    "autoHideControls": false,    // 진행 컨트롤 숨기기(키오스크)
    "autoInterval": 20,           // 자동 진행 문항 간격(초)
    "onlineRoom": false,          // 온라인 방(폰 참가)
    "fbUrl": "",                  // (선택) Firebase Realtime DB 주소
    "quizOnly": false             // 문제만 맞추기(영상·자동낭독 생략)
  }
}
```

- `content`·`album` 모두 배열 인덱스가 아니라 **곡 `id`로 키잉**되어, 곡을 추가·삭제·재정렬해도 어긋나지 않습니다.
- `album`이 없으면 `index.html` 내장 `ALBUM_INFO`가 폴백으로 쓰입니다(하위호환).
- 🧪 **새 곡을 추가할 땐 [데이터 파이프라인](DATA_PIPELINE.md)**(스테이징 → 검수 → 승격)을 따르세요. 검수용 스테이징 파일 `svt-data.staging.json`은 최상위에 `_review`(검수요청) 표식을 가질 수 있으며, 이는 프로덕션엔 싣지 않습니다.
- 곡을 추가하면 `u1001` 형태의 새 id가 부여됩니다(내장 곡은 `s2`~ — 초기 편집으로 일부 번호가 비어 있어 `s1`은 없음).

### 로드 우선순위
앱 시작 시 다음 순서로 데이터를 불러옵니다.
1. **이 기기의 편집본** (localStorage `svt_lyrics_quiz_v1`)
2. **커밋된 `svt-data.json`** (저장소 루트, http/https 호스팅에서만 fetch)
3. **파일 내장 기본값** (`DEFAULT_SONGS` / `DEFAULT_CONTENT` / `DEFAULT_CONFIG`)

설정 탭 **저장 슬롯**(🔒 비밀번호 잠금)의 **💾 배포본 저장(커밋용)** 버튼은 현재 상태를 위
`svt-data.json` 형식(= 아래 데이터 모델)으로 내려받습니다. 이 파일을 저장소에 커밋하면 2번 경로로
배포본에 반영되고, `rev` 값이 각 기기의 적용본보다 크면 모든 기기가 커밋된 데이터를 채택합니다.

### 필드 규격
| 필드 | 설명 | 예시 |
|---|---|---|
| `name` | 곡명 = **퀴즈 정답** | `아낀다 (Adore U)` |
| `part` | 파트 힌트(표시용) | `1절 벌스` |
| `diff` | 난이도 | `상` · `중` · `신곡` |
| `lyrics` | 낭독할 가사(1~2줄 권장, TTS 8~15초) | `너의 아픔 나로 덮어도 돼` |
| `mv` | 유튜브 주소 | `youtu.be` / `watch?v=` / `/embed/` / `/shorts/` / 11자 ID |
| `time` | MV 시작 시간 | `1:12` 또는 초 단위 `72` |
| `lang` | (선택) TTS 언어 고정 | `ko`/`en`/`zh`/`ja` |
| `read` | (선택) 한글 독음 — 원어 음성 없는 기기 대체 낭독 | `렛츠 킬 더 선라이즈` |
| `variants` | (선택) **곡당 여러 문제** — 각 항목이 별도 문제(정답은 같은 곡) | `[{lyrics,time,mv?,read?,lang?}, …]` |

> **variants(곡당 다문제)**: `content[id].variants`에 `{lyrics, time, mv?, read?, lang?}` 배열을 두면 한 곡에서 여러 문제가 출제됩니다(문항 키 `s60`·`s60#1`·`s60#2`…). 지정 안 한 필드(mv/lang 등)는 곡 기본값을 따릅니다. 도구: `node tools/add-variant.mjs --id s14 --lyrics "…" --time "0:40"`.

## 게임 모드 (`config.mode`)
| 값 | 모드 | 설명 |
|---|---|---|
| `normal` | 일반 | 범위 진행 → 결과·정답률(기본) |
| `battle` | 대결 | 팀 동시전, 고정 라운드 후 최고점 승리(동점 서든데스) |
| `infinite` | 무한 | 서바이벌(1오답 종료)·솔로·최고 연속기록 |

## 2. 입력 도우미

- **일괄 입력** — 번호 형식 텍스트를 붙여넣어 슬롯별 가사에 자동 배분
  ```
  1. 첫 번째 문항 가사
  2. 두 번째 문항 가사
  3) 세 번째도 가능
  4 = 등호도 인식
  ```
- **저장 슬롯**(🔒 관리자 전용, 비밀번호는 오너 보관 · 소스엔 해시만) — 현재 구성을 이름 붙여 여러 벌 저장/불러오기. 문항·가사 편집기도 이 관리자 잠금 뒤로 숨겨져 있어, 잠금 해제 후에만 노출됨(실서비스 일반 방문자에겐 비노출).
  **저장 시 `svt-data.json`이 자동으로 커밋용 다운로드**되어, 커밋하면 곧바로 배포본에 반영됩니다. 각 슬롯의
  **💾 배포본** 버튼으로 지난 구성도 `rev` 포함 `svt-data.json`으로 받을 수 있습니다.
- **불러오기(파일)** — 내려받은 슬롯/`svt-data.json`을 붙여넣어 복원(기기 간 이동)
- **기본값 복원** — 내장 56문항·설정으로 초기화

## 3. 구절 선정 가이드

**좋은 구절**
- 곡명·제목 키워드가 **포함되지 않은** 구간 (곡명이 나오면 즉답 처리됨)
- 후렴보다 **벌스·브릿지**, 문장이 완결되어 낭독 시 의미가 통하는 단위
- 해당 곡에만 나오는 고유 소재·상황 묘사

**피할 구절**
- 곡명이 그대로 등장하는 구간
- 영어 비중이 높은 구간 (한국어 TTS 발음 부정확)
- 의성어·추임새 위주 구간 (정보량 부족)

**타임스탬프** — 해당 가사가 나오는 시점보다 **3~5초 앞**을 지정하면 재생 직후 참가자가 화면에 집중할 시간이 확보됩니다.
