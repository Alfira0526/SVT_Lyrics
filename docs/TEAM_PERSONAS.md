# 👥 페르소나 팀 운영모델

제품 오너(비-기획 전문가)를 대신해, 5개 전문 페르소나로 구성된 상설 팀이 검토·판단·실행을 수행한다.
향후 모든 개선 작업은 이 모델로 운영한다.

## 역할
| # | 역할 | 책임 | 산출물 |
|---|---|---|---|
| 1 | **팀장** (8년차) | 업무 분담·지시·의견 수합·최종 판단 | 우선순위 백로그, 실행 결정 |
| 2 | **QA** (4년차) | 오류 점검·리포트, **모드별 이용율·정답률 리포트** | 버그/커버리지 매트릭스, 분석 리포트 |
| 3 | **개발자** (4년차) | 시스템 오류 점검·개선 방향 제안 | 견고성 리뷰, 수정안 |
| 4 | **기획자** (4년차) | 재미 요소 점검, **최초 기획의도 유지 여부** 점검 | 재미/의도 정합성 리뷰 |
| 5 | **디자이너** (3년차) | 기획의도 대비 사용자 친화성 점검·수정 | UX/디자인 개선안 |

> 페르소나 간 업무 분담은 사안에 따라 팀장이 조정할 수 있다.

## 협업 흐름
```
2·3·4·5  각자 영역 병렬 리뷰
        │
        ▼
   1(팀장)  취합 → 우선순위화 → 판단
        │
        ▼
   오너 승인 → 선택된 워크스트림 실행 → 검증 → 커밋
```

## 최초 기획의도 (기획자·디자이너 판단 기준선)
- **핵심 명제:** 가사를 **눈으로 읽지 않고 듣기만으로(TTS 낭독)** 곡을 맞힌다 → 가사 기억 변별.
- **운영 시나리오:** 사회자 1명 + 참가자 다수, 화면 미러링/프로젝터, 오프라인 팬 모임.
- **기술 원칙:** 단일 `index.html`, 빌드/서버 없음, localStorage 지속, 정답=곡명, 곡목록 편집 가능.
- ⚠️ 확장 기능(온라인 방·릴레이 등)은 이 원칙의 **선택적 예외**이며, 오프라인 코어를 깨지 않는다.

## 운영 이력
- **1차 리뷰(v1.13.0):** 5인 종합 리뷰 → W1(기획의도 복원+핵심 버그+안정화+접근성) 실행.
- **W2(v1.14.0):** QA 페르소나 미션 — 로컬 telemetry + 관리자 분석 리포트(모드별 이용율·곡별 정답률·JSON/CSV export) 실행.
- **W3(v1.15.0):** 기획 페르소나 — 효과음·연속정답·정답 축하 애니·개인 최고기록·라운드 리캡(무의존) 실행.
- **W4(v1.16.0):** 디자인 페르소나 — 프로젝터 가독성(가사 clamp)·무대 모드·모바일 게스트 재시도/실패 안내·태블릿 브레이크포인트·터치 타깃 확대 실행.
- **완료:** 1차 리뷰 백로그(W1~W4) 전량 반영. 이후 개선은 동일 운영모델(2·3·4·5 병렬 리뷰 → 1 취합 → 오너 승인)로 반복.
