> SVT_Lyrics(세븐틴 가사 퀴즈 · 단일 `index.html` 오프라인 웹앱) · 5인 페르소나 패널 공동 작성

## 0. 한 줄 요약

지금의 설정 화면은 **개별 토글이 10여 개** 흩어져 있어, 특히 **부저 대결(온라인 방 ON + 4지선다 OFF)** 처럼 여러 옵션의 "조합"으로만 성립하는 플레이를 유저가 스스로 찾지 못한다. 이를 **"상황을 고르면 config가 통째로 세팅되는 원터치 시나리오 버튼 5개"** 로 바꾸고, 지금의 상세 토글 화면은 **관리자(세부 설정) 뒤로** 접는다. 기존 config·토글 로직은 **그대로 두고 그 위에 시나리오 레이어만 얹어** 하위호환·저위험으로 간다.

### 1-2. 각 옵션의 config 매핑·동작 지점

- 모드 프리셋: `MODE_DEFAULTS`(2668–2672)가 모드 선택 시 일부 필드를 **설정만 하고 잠그지 않음**(주석 2660–2662: 하드 잠금은 부저·팀블라인드를 막아서 제거됨). → **이미 "프리셋이 config를 통째로 설정하는" 패턴이 코드에 존재**한다. 시나리오는 이 구조의 확장판.
- UI→config 바인딩: 2404–2424행에 각 토글의 `change`/`input` 핸들러가 1:1로 존재. config→UI 역동기화는 `renderSetup()`(2644–2663).
- 시작: `#setup-start` → `startGame()`(3104).

### 1-3. 부저 게이트 (오너가 못 찾던 그 기능)

- 방장 판정 패널 진입 조건: `renderMc()`(1580–1581) —
  `if(config.onlineRoom && Room.host.active){ if(!config.mc){ Room.hostRenderBuzz(); return; } }`
- 즉 **부저 = `onlineRoom:true` + `mc:false`**. 두 토글을 정확히 반대 방향으로 맞춰야만 나타나며, `mc` 기본값이 `true`라 유저는 "온라인 방"만 켜고 4지선다는 그대로 둬서 **부저에 절대 도달하지 못한다.** ← 이번 개편의 1순위 해결 대상.

### 1-4. 관리자 잠금 구조 (분리에 재사용할 패턴)

- `SLOT_PW_HASH=3726493666`(3151), 해제 로직 3167–3177: 비번 일치 시 `document.body.classList.add("admin-open")`.
- CSS 게이트: `#editor-block{display:none}` / `body.admin-open #editor-block{display:block}`(290–291). 문항 편집기가 이미 이 잠금 뒤에 있음.
- **동일 패턴으로 상세 설정을 `body.admin-open`(또는 더 가벼운 "세부 설정 열기") 뒤로 넣으면 된다.**

## 2. 제안 ① — 일반 유저용 원터치 시나리오 버튼 세트

### 2-1. 설계 원칙

1. **상황(누구와·어디서·어떻게)** 을 고르면 config가 **통째로** 세팅된다. 유저는 옵션 이름(4지선다·teamBlind…)을 몰라도 된다.
2. 탭 → **바로 시작** 또는 **최소 확인(문제 수·범위, 필요 시 팀 이름) 1스텝** 후 시작.
3. **부저를 독립 버튼으로 전면 노출** — 조합을 유저가 만들 필요가 없게 한다.
4. 각 시나리오는 관련 필드를 **명시적으로 전부 지정**(잔여 설정 누수 방지 — 2665행 주석의 교훈).

### 2-2. 시나리오 → config 매핑 표 (핵심 산출물)

아래 5개를 기본 세트로 제안한다. (선택지 6번째는 2-4 참고)

| 시나리오 버튼 | 상황 한 줄 | `mode` | `teamMode` | `mc` | `onlineRoom` | `teamBlind` | `quizOnly` | `autoHost` | `autoHideControls` | `hideLyrics` | `timerOn/Sec` | 시작 흐름 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 🎧 **혼자·가볍게 듣기** | 한 명이 편하게 감상하며 맞히기 | normal | false | false | false | — | false | false | false | **true** | on / 20 | 바로 시작 |
| ⚔️ **같은 화면 팀대결** | 한 화면 앞에 모여 팀으로 승부(4지선다) | battle | true | **true** | false | true | false | false | false | true | on / 20 | 팀 이름 확인 → 시작 |
| 📱 **온라인 방(폰 4지선다)** | 각자 폰으로 참가해 보기 중 고르기 | battle | true | **true** | **true** | true | false | false | false | true | on / 20 | 팀·방 확인 → 시작(방 코드) |
| 🖐 **온라인 부저 대결** | 폰으로 먼저 누르기 승부(주관식·부저) | battle | true | **false** | **true** | true | false | false | false | true | on / 20 | 팀·방 확인 → 시작(방 코드) |
| 🎦 **무대·자동진행(프로젝터)** | 진행자 없이 스크린에서 저절로 흐르기 | normal | false | **true** | false | — | false | **true** | **true** | true | on / 20 | 바로 시작(키오스크) |

> 표기: `—` = 해당 시나리오에서 의미 없어 건드리지 않음(또는 기본 유지). 굵게 = 그 시나리오의 **정체성을 만드는 핵심 필드**.
> `scope`·문제 수·`teamNames`·`sfx`·`fbUrl`은 시나리오가 강제하지 않고 **직전 값/기본값 유지**(2-3 확인 스텝에서 조정). `mode`는 점수판·서바이벌 등 화면 동작을 좌우하므로 시나리오마다 명시.

**부저 시나리오가 표에 독립 버튼으로 존재 = 오너가 못 찾던 문제의 직접 해결.** `mc:false`+`onlineRoom:true`가 한 번에 세팅되어 `renderMc()`의 부저 게이트(1581)로 곧장 진입한다.

### 2-3. 탭 → 시작 흐름 (버튼별)

- **바로 시작형**(🎧 혼자, 🎦 무대): 탭하면 config 적용 후 곧바로 `startGame()`. 단, 카드에 "문제 수·범위"만 접근 가능한 작은 링크를 남겨 원하면 조정.
- **1스텝 확인형**(⚔️ 팀대결, 📱 온라인, 🖐 부저): 탭 → **경량 확인 시트**(팀 이름 / 문제 수·범위 / 온라인은 방 안내) → "시작". 이때 노출 항목은 **팀 이름·문제 수·범위** 정도로 제한.
- 온라인 계열(📱🖐)은 시작 시 기존 로직대로 **방 코드**가 뜨고 참가자는 "🔗 방 참가"로 입장. Firebase URL이 필요한 사용자는 세부 설정에서 1회 입력(2-4의 관리자 영역).

### 2-4. 6번째 후보 & 확장 여지 (선택)

- ♾️ **무한 서바이벌(혼자 최고기록)**: `mode:infinite, teamMode:false, mc:true, hideLyrics:true` — 기존 `MODE_DEFAULTS.infinite`와 동일. 리텐션용으로 추가 가치가 있어 **후보로 권장**하되, 첫 릴리스는 5개로 집중 후 반응 보고 추가.
- 시나리오는 **데이터(배열)로 정의**해두면(각 항목 = 아이콘·이름·설명·config패치·시작모드) 추후 추가/문구 변경이 코드 최소 수정으로 가능.

## 3. 제안 ② — 관리자(상세 설정) 분리 방안

### 3-1. 무엇을 어디로

**일반 유저 화면(기본)에 남길 것 — 최소:**
- 시나리오 버튼 5개(2장)
- 문제 수(`#intro-counts`) + 유닛곡 비중
- 문제 범위(`#scope-dims`/`#scope-vals`)
- (선택) 제한 시간 세그먼트 1줄 — 부담 적고 자주 쓰므로 남겨도 무방

**"세부 설정"(접힘/잠금) 뒤로 보낼 것 — 개별 토글 전체:**
- `c-hide, c-sfx, c-team(+에디터), c-mc, c-teamblind, c-quizonly`
- 기존 고급(`c-autohost, c-autointerval, c-autohide, c-online, c-fburl, voice-check`)

### 3-2. 두 단계 게이트 (권장)

현재 코드에 **두 종류의 잠금 패턴**이 이미 있다 — 이를 재사용:

1. **"세부 설정 열기"(무잠금, 접힘)** — 파워유저가 시나리오를 미세 조정하고 싶을 때. 지금의 `<details class="setup-adv">`(620)를 **모든 개별 토글을 감싸는 형태로 확장**. 비번 없이 펼침. 대다수 유저는 안 펼침.
2. **"관리자"(비번 잠금)** — 운영자만 봐야 할 것(Firebase URL, 키오스크/자동진행, TTS 점검, 문항 편집기). `body.admin-open` 패턴(290–291, 3167–3177) 재사용. `#editor-block` 옆에 상세 설정 블록을 같은 게이트 뒤로.

> 실용 권고: **개별 플레이 토글(6~11번)은 무잠금 `<details>`** 로, **운영·인프라 토글(12~17번)은 비번 잠금** 으로 나눈다. 부저처럼 조합이 필요한 것은 이미 시나리오 버튼으로 노출되므로, 세부 토글을 깊이 감춰도 일반 유저 도달성에는 문제가 없다.

### 3-3. 하위호환 포인트

- 세부 설정 안의 토글들은 **지금의 id·핸들러(2404–2424)·`renderSetup()`(2644)을 그대로 유지**한다. 시나리오 버튼이 하는 일은 "이 토글들이 하던 `config.x=…; saveState();`를 한 번에 실행"하는 것뿐. → 로직 중복/재작성 없음.

## 4. 제안 ③ — 정보구조(IA) 재구성

### 4-1. 화면 흐름 스케치 (텍스트)

```
[인트로]
  ↓  "게임 시작"
[시나리오 선택]  ← 새 기본 화면
  ┌─────────────────────────────────────────────┐
  │  어떻게 플레이할까요?                          │
  │                                               │
  │  [🎧 혼자·가볍게]   [⚔️ 같은화면 팀대결]        │
  │  [📱 온라인 4지선다] [🖐 온라인 부저대결]        │
  │  [🎦 무대·자동진행]                            │
  │                                               │
  │  문제 수 [− 15 +] [전체]   범위 [전체 ▾]        │
  │                                               │
  │  ▸ 세부 설정 열기(접힘)   🔒 관리자             │
  └─────────────────────────────────────────────┘
        │ 바로 시작형 ─────────────► [게임]
        │ 1스텝 확인형
        ↓
[경량 확인 시트]  (팀 이름 / 문제 수·범위 / 온라인 방 안내)
        ↓  "시작"
[게임]  (온라인 계열은 방 코드 표시)
```

### 4-2. 원칙

- **인트로 → 시나리오 → (최소 확인) → 시작.** 기본 경로에서 개별 토글을 마주치지 않는다.
- 시나리오 카드는 **아이콘 + 이름 + 한 줄 설명**만(모드 카드 538–540 스타일 재사용 가능).
- "세부 설정 열기"·"관리자"는 화면 **하단에 작게**. 있는 걸 알지만 눈에 먼저 들어오진 않게.
- 선택된 시나리오는 시각적으로 강조(기존 `.mode-card.sel` 스타일 402 재사용).

## 5. 제안 ④ — 단계별 구현 계획 (제안, 미구현)

> 원칙: **기존 config/토글/핸들러는 유지**하고, 그 위에 **시나리오 레이어만 얹는다.** 하위호환·저위험. (`MODE_DEFAULTS`/`selectMode` 2668–2676이 이미 같은 발상 — 확장이지 재작성이 아님.)

| 단계 | 내용 | 리스크 | 검증 포인트 |
|---|---|---|---|
| **P0. 시나리오 데이터 정의** | 2-2 표를 `SCENARIOS` 배열로(아이콘·이름·설명·configPatch·startMode). 순수 데이터, 로직 없음 | 없음(데이터만) | 5개 patch가 2-2 표와 1:1 일치하는지 리뷰 |
| **P1. 시나리오 UI + 적용 함수** | 선택 화면 렌더 + `applyScenario(id)` = `Object.assign(config, patch); saveState(); renderSetup()` (기존 `selectMode` 패턴 재사용) | 낮음 | 각 버튼 탭 후 `config` 스냅샷이 표와 일치 |
| **P2. 부저 경로 E2E** | 🖐 시나리오 → 시작 → `renderMc()` 부저 게이트(1581) 진입 확인 | 중(핵심 목표) | `onlineRoom:true`&`mc:false`로 방장 부저 판정 패널이 실제로 뜨는지 |
| **P3. 세부 설정/관리자 분리** | 개별 토글을 `<details>`(무잠금)로, 인프라 토글을 `admin-open` 게이트로 이동 (마크업 재배치, id 유지) | 낮음 | 이동 후에도 2404–2424 핸들러·`renderSetup` 정상, 문항 편집기 잠금 회귀 없음 |
| **P4. 경량 확인 시트 + 1스텝 흐름** | 확인형 3개 시나리오의 팀/문제수/범위 시트 | 낮음 | 시트에서 조정한 값이 config·게임에 반영 |
| **P5. 하위호환·회귀** | 기존 저장 상태(localStorage `svt_lyrics_quiz_v1`) 로드 시 시나리오 미선택 상태로도 정상 시작 | 중 | 구버전 config 로드 → 크래시 없이 기본 화면 |

**저위험 판단 근거**: 시나리오는 기존 필드에 값만 대입한다. 새 config 필드·저장 스키마 변경이 없어 구버전 상태와 충돌하지 않는다. 실패 시 시나리오 레이어만 걷어내면 기존 화면이 그대로 남는다(롤백 용이).

**주의(누수 방지)**: 시나리오 patch는 관련 필드를 **전부 명시**해야 한다. 예로 온라인→오프라인 시나리오 전환 시 `onlineRoom:false`를 빠뜨리면, 2665행 주석이 경고하듯 이전 방 설정이 남아 게임 대신 방 로비로 샌다. 표(2-2)의 빈칸은 "의도적으로 유지", 굵은 값은 "반드시 세팅"으로 구현 시 구분.

## 6. 페르소나 관점

- **기획**: 유저는 "4지선다/teamBlind"가 아니라 **"오늘 누구랑 어떻게 노는가"** 로 사고한다. 상황을 팔면 조합은 저절로 맞는다 — 특히 부저는 "재미의 하이라이트"인데 지금 도달률 0에 가깝다. 시나리오 이름/아이콘의 감정선(모임·승부·무대)이 곧 재미의 예고편.
- **디자인**: 토글 11개는 인지 부하이자 이탈 지점. **버튼 5개 + 최소 2필드**로 첫 화면을 비우면 도달성이 급상승한다. 선택된 카드 강조·"세부/관리자는 하단에 작게"로 시각적 위계를 명확히.
- **개발**: `MODE_DEFAULTS`/`selectMode`가 이미 "프리셋으로 config 통째 설정" 패턴을 증명했다. 시나리오는 그 확장이라 **신규 스키마·저장 변경 0**, 하위호환 안전. 유일한 함정은 patch의 필드 누락(방 로비 누수) — 전 필드 명시로 방지.
- **QA**: 회귀 스위트의 핵심은 (a) 5개 시나리오 각각의 config 스냅샷 == 표, (b) 🖐 부저 E2E 게이트 진입, (c) 세부/관리자 이동 후 기존 토글·문항편집기 잠금 정상, (d) 구버전 localStorage 로드. 온라인 2종은 방 코드·참가·채점까지 확인.
- **팀장**: 목표는 **"부저를 유저가 찾게 하는 것"** 과 **"첫 화면 단순화"** 두 가지. 나머지는 이 둘을 해치지 않는 선에서.

## 7. 팀장 권고 — 무엇부터, 무엇을 뒤로

**먼저(1순위, 즉시 착수):**
1. **시나리오 5버튼 + 부저 독립 노출**(P0–P2). 오너의 최우선 고통(부저 미발견) 직접 해소. 저위험·고효과.
2. **첫 화면 최소화** — 시나리오 + 문제 수·범위만 남기고 개별 토글을 `<details>`로 접기(P3 전반).

**다음(2순위):**
3. 경량 확인 시트·1스텝 흐름(P4)로 팀/온라인 시나리오 완성도 up.
4. 회귀·하위호환 검증(P5) 통과 후 릴리스.

**뒤로(후순위·의도적 보류):**
- **인프라·운영 토글(Firebase URL·자동진행·키오스크·TTS 점검·문항 편집기)** 은 **비번 관리자 뒤**로. 일반 유저 화면에서 완전히 제외.
- **6번째 시나리오(♾️ 무한)** 는 5개 릴리스 후 반응 보고 추가.
- **모드 카드 하드 잠금 재도입** 은 하지 않는다(2660–2662 교훈: 부저·팀블라인드를 막아 역효과).

**핵심 원칙(재확인):** 기존 config·토글·핸들러는 **건드리지 말고**, 그 위에 시나리오 레이어만 얹는다. 언제든 레이어만 걷어내면 원상복구되는 **저위험·하위호환** 경로로 간다.
